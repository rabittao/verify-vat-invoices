# OCR复核、纠错与归档一致性

## 触发与证据

用户要求查原因时只读诊断；用户授权修正时才更新提取结果和清单。已经授权批量复核并修正，无需逐票再询问。

1. 从 manifest 筛选待复核项，以 PDF文件名、从1开始的页码、完整票号定位原PDF、OCR JSON、正式查验截图和 `运行证据/<票号>/平台结果与核对.json`。先记下原标记及字段值。
2. 重新渲染原PDF指定页（可用 pdftoppm），逐字看原票与正式截图差异区域；必要时放大裁剪。OCR文本、平台DOM文本只辅助定位，不能以两段机器文本相同代替图像对照。组图必须标出来源与页码，防止串票。扫描PDF无可靠文字层时以像素为准。
3. 判定：OCR识别错字、比较器误判、实际票面差异或证据不足。只修正已看清且两份原始证据一致的字段。实际不一致或看不清保持待复核，单独列票号、页码、字段、双方值及截图链接。

## 本次已验证的易错类型

以下是复核线索，不是自动替换字典；相似字符不能全局替换。

| 字段 | 观察到的OCR错误 | 处理 |
|---|---|---|
| 识别号 | 数字1误为I；字母F误为E；U误为0；L误为1；大写X误为小写x | 对照原PDF和截图逐位确认完整18位编号，再修正具体记录 |
| 名称 | 广→厂、责→贡、嘉→慕、南通→阐迪 | 逐票确认真实名称；不宽松匹配或批量替换企业名称 |
| 不征税金额 | 原票税额为星号、平台税额为空，合计只返回一个金额 | 明确“不征税/免税”、原记录税额为0、金额等于价税合计后，复用现有单金额规则 |
| 提取缺项 | 识别号正则仅接受大写，OCR含小写后完全未提取 | 先确认原字符，不把“缺项”当真实税号不同 |

`workspace_archive.compare_platform_text` 已支持限定“合计”至“价税合计”区间的金额提取，以及明确免税/不征税且原税额为零的单金额核对。旧标记可能在修复前生成；先用现有代码重算，避免再改代码或硬设一致。常规应税票不能套用空税额等于零。

`expected_parties` 当前依赖固定坐标区域；新PDF布局须验证，不可把提取失败当票面差异。保留严格完整税号和名称比较，降低误报靠校正有证据的OCR，不靠降低标准。

## 授权修正后的写入流程

- 使用现有 `workspace_archive.archive_lock(root)`，备份原OCR、manifest、总表、文件夹清单、逐票核对证据、results及将更新的success checkpoint。先做全部候选的预检，错误时保留备份并报告，避免留下无说明的部分更新。
- OCR仅修正已确认的那一行，保留原始 `text`（如 `original_text_before_review`）、复核时间和说明；保留原置信度，不伪造新的模型置信度。原PDF与正式截图不修改。
- 保存逐票审计：票号、PDF、页码、字段、修正前值、原PDF确认值、平台截图确认值、原因、结论、证据路径和截图SHA256。生成便于用户阅读的报告及CSV，实际差异单列；没有差异也明确0张。
- 对修正后的OCR调用现有 `compare_platform_text` 重算全部检查，使用匹配票号的真实详情文本。不能直接把所有 false 改 true。
- 更新 `平台结果与核对.json`，保留旧逐项核对和人工复核依据；调用 `save_records` 同步 manifest、总表及所有文件夹清单。更新该票成功记录的 `archive_check` 与复核说明，存在success checkpoint时同步；历史尝试次数、失败记录、验证码候选不改写。
- 写入后重新读取并验证：所选目标范围均按证据得到正确状态，非目标记录未改变；三份清单路径、页码、票号、状态和核对字段一致；逐票证据与最新成功记录一致。全量正式截图数量和SHA256应与修正前相同。
- 复用 `verify_archived` 做清单回读，但用同一截图作source只能验证路径/清单，不能证明截图未变化；必须另与修正前保存的SHA256比较。
- 运行归档回归测试；若新增比较逻辑，测试应覆盖真实差异仍保留待复核、错票拒绝、常规应税票不被不征税规则放过。仅数据纠错不需要为错字造通用替换逻辑。

## 验收边界

复核报告必须基于当前批次证据，不能推断所有待复核项都是OCR错误。归档完成与字段一致分别验收；保留每张实际差异或证据不足项的双方值、来源、原因与本地证据链接。技能只保存通用流程，不保存真实票号、企业信息、批次文件名或原始票据。
