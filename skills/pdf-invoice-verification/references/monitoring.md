# 监控与通知

用户要求监控时使用 `automation_update`，先读取现有 automation 配置，保留周期、通知偏好等字段，更新现有任务而非重复创建。工具不可用时如实说明没有建立持续监控，不用临时轮询冒充定时任务。

可复用的监控提示（替换项目绝对路径）：

> 只读监控指定项目 output/resume/runner.pid 对应进程的真实命令行，以及 run-status.json、run.log、results.json 和上一级 .核对工作/manifest.json。核验新增成功票的截图确实位于原 PDF 同名文件夹，文件名中的页码和票号一致；核对发票查验核对总表.csv、文件夹核对清单.csv 的路径、状态和核对字段，检查 archive_verified、archive_sha256 与实际截图 SHA256。发现查验成功未归档或清单不一致立即报告具体票号及缺失项。正常推进、状态不变时保持安静。仅新增已验证归档、程序结束/异常退出、连续5张未取得详情或需要用户操作时通知；给出成功、失败、暂缓、待处理数量和最近原因。新增成功逐张列完整票号、原PDF名称及页码、本地截图链接，只报尚未通知的票。通知在当前聊天中进行，不上传发票资料、截图或密钥。监控不得重启程序或重置预算；用户要求停止则不重启。程序停止或本轮完成，且没有已授权补跑队列等待或运行时，报告并暂停监控。

统计按每票、本轮最新终态去重，不能把 retries/results 数组长度当发票数。失败和暂缓仍是全量未归档的一部分；报告本轮待办时注明是否包含它们，避免重复加总。正在限流等待不是终态失败。没有之前通知基线时从聊天或既有监控状态恢复，无法确认就说明无法判定“新增”，不要把所有成功重复推送。

只读核查不修改发票清单，也不因状态过久自动启动新一轮。修改通知去重状态仅限现有监控自身状态，不写发票业务数据。后台程序停止且没有等待或运行中的授权队列时，按用户要求暂停对应 automation，不能只在回复中说暂停。

## 多队列与最终完成

检查每组已授权队列的独立状态文件、真实PID、计划预算和前序依赖，不仅是默认队列。只要任一队列等待或运行，监控继续，不在主进程切换时暂停。前序被停止或异常时核实后序取消；监控不启动新队列。

正常退出会删除 runner.pid，切换时也可能暂缺；结合 run-status、队列退出码和实际进程判断，不把文件缺失直接当程序崩溃。

最终完成须全部队列结束、无残余进程和未完成的授权范围，再调用 automation_update 暂停监控。全部归档不等于全部字段一致，必须单独报告待复核数量。用户授权修正后按 reconciliation.md 操作；只读监控不修改业务记录。
