# PDF 电子发票查验与归档

交付目标：每张发票对应一张真实税务平台详情截图，存入原 PDF 同名文件夹；记录字段核对结论、失败原因和待处理项。默认中文沟通。

## 安装与跨电脑使用

将本技能目录复制到 Codex 的技能目录（通常为 `~/.codex/skills/pdf-invoice-verification`），重载技能后使用 `$pdf-invoice-verification`，并在请求中指定项目和PDF目录。技能本身不包含运行依赖、密钥或业务数据。首次运行读取 [跨电脑准备](references/setup.md)。

## 先定位当前状态

复用用户指定的 `verify-vat-invoices` 项目。先定位实际项目目录和资料根目录，不依赖技能安装位置推断项目路径。源码来源为 `https://github.com/rabittao/verify-vat-invoices`。

先读项目 `AGENTS.md`（若有）、现有脚本和状态。检查 `output/resume/runner.pid` 对应进程的命令行，不能仅凭 PID 文件认定在运行，也不要影响用户其他浏览器。已有进程时不重复启动。用户只要求分析时只读诊断，后台继续。

- 已有 `.核对工作/manifest.json`：按 [续跑与归档](references/workflow.md) 验证依赖后运行。
- 新 PDF：先提取并校核字段，再建立归档所需清单；通用流水线不会自动创建本工作区续跑清单。详细边界见同一参考文件。
- 用户要求监控或继续监控：按 [监控规则](references/monitoring.md) 使用应用自动化工具更新已有任务，不创建重复监控。
- 字段差异与批量复核：按 [OCR复核与修正](references/reconciliation.md) 逐票取证、备份、重算和同步清单。

## 查验与预算规则

目标页面：`https://inv-veri.chinatax.gov.cn/fpcygzfw/national-invoice-check`。优先使用项目真实实现，不猜接口、地区路由或选择器。默认一个后台浏览器、同一标签页，避免反复弹窗。

仅在提示为“请输入验证码文字”时识别；颜色提示刷新。独立图片内容检查和识别必须一致，仅接受完整英文字母/数字；中文、未知、漏字或检查不一致时刷新，不消耗每票 3 次有效候选预算。不能承诺模型零漏检。

刷新至少间隔 10 秒，实际提交至少间隔 65 秒。一分钟限流等待后继续，连续限流最长等待 5 分钟；每日上限停止当前票。40 次筛选仍无候选则暂缓该票；网络刷新最多 3 次，页面恢复最多 2 次，避免单票无限卡住。具体参数以当前源码为准。

点击超时不等于未提交：先查看网站自己的请求、响应和详情，不盲目重复点击。新版消息条不一定有“确定”，仅在实际对话框内操作。请求失败、403、验证码错误、字段差异分别记录，不混为识别失败。

**续跑与新一轮重试分开。** 当前 `--retry-plan` 配合 `retry_plan.js` 持久化每票已用次数；精确范围和队列衔接按 [续跑与归档](references/workflow.md) 执行。不带计划的普通续跑器仍会重置每票内存计数。只有用户明确要求重试已耗尽次数的票时，才建立保留历史记录的新一轮计划；监控本身不提供重试授权。

## 成功与归档必须分别核验

识别成功、按钮点击成功均不代表查验成功；仅真实返回详情且票号匹配，才可保存为该票结果。归档应校核票号、日期、金额税额、价税合计、购销双方名称和识别号。

正式截图路径为 `<PDF文件名去扩展名>/<三位页码>_<完整票号>_查验结果.jpg`。回读截图、SHA256、manifest、总表及文件夹清单，状态和路径一致后才报告归档成功。归档失败保留详情文本、截图和 checkpoint，优先本地恢复，避免重复查验。

字段差异对照原 PDF 和详情截图逐项解释；OCR 错字不能泛化成宽松名称匹配。不征税单金额仅在明确不征税/免税且原税额为零时处理。真实差异或证据不足保留待复核，不为提高成功率改标记。并发修正清单使用现有归档锁和原子写入。

成功且归档回读通过后可清理该票临时图片；正式截图保留。失败保留普通文字验证码和错误现场；不要批量删除正在写入的文件。

## 数据与验证边界

只读取密钥是否配置，不输出密钥。Qwen 提取会发送票面图片，DeepSeek 验证码识别会发送验证码，视觉结果兜底可能发送发票详情；执行前核实此用途在用户授权范围内，缺少授权时只确认缺失部分。制作 skill 本身不触发外部查验。不得把票据、日志、截图、清单或 `.env` 纳入公共仓库。

修改逻辑后运行项目 JS 和 Python 测试。离线测试不等于实站成功：需要实站验证时先跑一张未归档发票，确认详情和正式归档，再扩大续跑。用户要求停止时停止指定程序并暂停监控，不自动恢复。
